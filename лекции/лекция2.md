# Введение в C++
## Язык программирования C++
язык программирования C++ представляет собой высокоуровневый язык общего назначения /b со статической типизацией, своими корнями он уходит в язык C, /b который был разработан в 1969-1973 годах компанией Bell Labs программистом Деннис Ритчи.
В начале 80-х годов Датский программист Бьерн Страуструп работал в компании Bell Labs, разработал C++, как расширение к языку C. В начале просто расширял язык C с некоторыми возможностями. Изначально язык назывался C с классами.
C+++ является компилируемым языком, а это значит что компилятор транслирует исходный код на C++ в исполняемый файл, содержащий набор машинных инструкций.

### Зачем нужно компилировать исходные файлы:

Исходный C++ файл это всего лишь код, но его невозможно запустить как программу или использовать как библиотеку, поэтому каждый использованный файл требуется скомпилировать в исполняемый

### Этапы компиляции

1. препроцессинг - макро процессор, который преобразовывает программу для дальнейшего компилирования. На данной стадии происходит работа с препроцессерованиии с директивами. Добавляет хэдеры в код. (#include)
2. Компиляция - это процесс преобразования исходного кода, написанного на языке программирования высокого уровня (например, C++, Java, Python), в машинный код или в другой низкоуровневый язык, который может напрямую выполнить процессор компьютера. 
3. Ассемблирование - перевод ассемблерного кода в машинный. Объектный файл - созданный компилятором файл, содержащий кусок машинного кода, этот кусок кода, пока что не свзяанный с другим, называется объектом кода.
4. Компоновка. Компоновщик (Линкер) - связывает все объектные файлы и статические библиотеки в единый исполняемый файл, который мы можем запустить.
5. Загрузка

## Файлы решения (Solution)

.sln — файл решения. Может содержать несколько проектов. Хранит ссылки на них, конфигурации сборки (Debug/Release, x86/x64).

## Файлы проекта

.vcxproj — XML-файл проекта. Список исходников, настройки компилятора/линковщика, пути к include/lib, платформа.
.vcxproj.filters — организация файлов по виртуальным папкам в Solution Explorer (не влияет на сборку, чисто визуальное).
.vcxproj.user — пользовательские настройки (например, аргументы командной строки для отладки). Не коммитить в git — уникально для каждого разработчика.

## Исходный код

main.cpp / <ИмяПроекта>.cpp — точка входа, main().
pch.h / pch.cpp (или stdafx.h/.cpp в старых версиях) — precompiled header. Ускоряет компиляцию: сюда кладут стабильные системные заголовки (<iostream>, <vector> и т.п.), которые редко меняются.
framework.h — обычно только #include <windows.h> с исключением редко используемых частей WinAPI (актуально для Windows-проектов).

## Папки при сборке

Debug/ Release/ — промежуточные и выходные файлы конкретной конфигурации (.obj, .exe, .pdb).
x64/ — если целевая платформа x64, эти папки будут вложены сюда.
.vs/ — служебная папка IDE (кэш IntelliSense, настройки окна). Всегда в .gitignore.

## Что коммитить в git
.sln, .vcxproj, .vcxproj.filters, все .cpp/.h. Игнорировать: .vcxproj.user, .vs/, Debug/, Release/, x64/.
